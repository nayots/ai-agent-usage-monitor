# Edge-Docked Mini Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-line strip pinned to the top or bottom edge of the screen showing, per visible provider, its monogram, one bar and one percentage — the always-visible form the 16-pixel tray glyph currently approximates.

**Architecture:** A second `Window` bound to the same `MainViewModel`, so it costs no new data path and cannot disagree with the widget. Mini mode and the full widget are mutually exclusive: showing one leaves the other. Docking is a pure function over the strip's size and the monitor work area, testable without a monitor, in the same shape as the existing `PlacementClamp`.

**Tech Stack:** .NET 10, WPF, xUnit.

This implements **C19** from `docs/specs/2026-08-13-feature-inventory-and-ideas.md` §2.2. It is **not** compact density (`WidgetDensity.Compact`), which shrinks the same window; this is a different presentation of the same model.

## Global Constraints

Every task's requirements implicitly include this section.

- **Warnings are errors.** `dotnet build` must finish with `0 Warning(s)`.
- **Run build and test as separate commands, never chained.**
- **The build lock is expected, not a defect.** The user's `AiUsageMonitor.App.exe` may be running and holding `src/AiUsageMonitor.App/bin/…`, making a plain `dotnet build` fail with `MSB3021`. **Never kill that process.** Build and test with:
  - `dotnet build -p:BaseOutputPath=$env:TEMP/aium-build/`
  - `dotnet test -p:BaseOutputPath=$env:TEMP/aium-build/`
- **Missing data is `null` and renders as an explicit absence marker — never as `0`, and never as an empty bar that reads like 0%.**
- **The domain model stays provider-neutral**; nothing branches on which provider it is.
- **The strip is a projection of the cards, never a second opinion.** Bar tone comes from the same `QuotaBarFillSelector` the widget and the tray glyph use; a stale card's bar greys here exactly as it does there.
- **No administrator privileges**, no new `PackageReference`.
- **Windows-only WPF.** Multi-monitor and per-monitor DPI must work: use `ScreenBounds.WorkAreaFor(window)`, never `SystemParameters.WorkArea`. Read the XML doc on `ScreenBounds` — it explains why.
- **One commit per task**, created serially.

## The rule that decides the shape

Mini mode and the widget window are **mutually exclusive**. Showing the full widget — from the tray's `Open`, from the global hotkey, from the single-instance broadcast, from a click on the strip — turns mini mode off. Turning mini mode on hides the widget. There is never a moment when both are on screen, so nothing has to decide which one owns the placement, the dismissal timer, or the tick cadence. Do not introduce a "both visible" state to save a line.

### Task 1: The mode setting and the primary window

**Files:**
- Modify: `src/AiUsageMonitor.Infrastructure/Settings/AppSettings.cs`
- Modify: `src/AiUsageMonitor.App/ViewModels/ProviderCardViewModel.cs`
- Test: `tests/AiUsageMonitor.Infrastructure.Tests/AppSettingsStoreTests.cs`, `tests/AiUsageMonitor.App.Tests/ProviderCardViewModelTests.cs`

**Interfaces:**
- Produces:
  ```csharp
  namespace AiUsageMonitor.Infrastructure.Settings;

  /// <summary>Which screen edge the mini strip is pinned to.</summary>
  public enum MiniDock { Top, Bottom }

  // on AppSettings
  /// <summary>
  /// The edge-docked one-line strip instead of the widget window (PRD §28). Persisted, unlike the
  /// title bar's pin: this is how the user wants to read the widget from now on, not what they are
  /// doing this minute.
  /// </summary>
  public bool MiniMode { get; init; }
  public MiniDock MiniDock { get; init; } = MiniDock.Top;

  /// <summary>
  /// Where along its edge the strip sits, or null before it has ever been placed. Null rather than
  /// 0 for the same reason <see cref="WindowLeft"/> is: 0 is a position a user could have chosen.
  /// </summary>
  public double? MiniLeft { get; init; }

  // on ProviderCardViewModel
  /// <summary>
  /// The first window this provider reported, or null when it has reported none. "First" is the
  /// provider's own answer — windows arrive in provider order and are never re-sorted — and it is
  /// the same window the tray glyph takes its digits from, so the strip and the glyph can never
  /// disagree about which limit they are showing.
  /// </summary>
  public QuotaRowViewModel? PrimaryWindow { get; }
  ```

**Requirements:**

- `PrimaryWindow` is `Windows.Count > 0 ? Windows[0] : null`. `RebuildWindows` must raise change notification for it in the same place it already raises `HasWindows`, or the strip will show the first snapshot forever.
- `MiniDock` serializes as its enum name, matching how `ThemePreference` and `WidgetDensity` already serialize. Verify by round-trip, not by assumption.
- An unrecognised `MiniDock` value in a hand-edited settings file must fall back to `Top` rather than throwing. Check how `AppSettingsStore` currently handles an unknown enum name and follow it; if it currently throws, that is a defect this task fixes for all three enums.

**Acceptance criteria (tests to write):**

- `PrimaryWindow` is null before any snapshot, is the first row after a two-window snapshot, and changes when a new snapshot reorders or replaces the windows.
- A property-changed notification for `PrimaryWindow` is raised by `Apply`.
- `AppSettings` round-trips `MiniMode`, `MiniDock` and `MiniLeft` through `AppSettingsStore`.
- A settings file containing `"MiniDock": "Sideways"` loads with `MiniDock.Top` and does not throw.

- [ ] **Step 1:** Add the enum and the three settings; add `PrimaryWindow`.
- [ ] **Step 2:** Write the tests; build and test as separate commands.
- [ ] **Step 3:** Commit — `feat: add the mini-mode setting and a primary-window projection`.

### Task 2: The docking rule and the strip

**Files:**
- Create: `src/AiUsageMonitor.App/Interop/MiniPlacement.cs`
- Create: `src/AiUsageMonitor.App/Views/MiniWindow.xaml`, `MiniWindow.xaml.cs`
- Test: `tests/AiUsageMonitor.App.Tests/MiniPlacementTests.cs`, `MiniWindowTests.cs`

**Interfaces:**
- Consumes: `MiniDock`, `PrimaryWindow` (Task 1).
- Produces:
  ```csharp
  public static class MiniPlacement
  {
      /// <summary>
      /// Where a strip of <paramref name="size"/> sits on <paramref name="workArea"/>, given the
      /// edge it is docked to and the horizontal position the user last dragged it to. Pure, so the
      /// rule is testable without a monitor — the same reason <see cref="PlacementClamp"/> is.
      /// </summary>
      public static Point Fit(Size size, Rect workArea, MiniDock dock, double? desiredLeft);
  }

  public partial class MiniWindow : Window
  {
      public MiniWindow(MainViewModel model, SettingsService settings);
      public event EventHandler? ExpandRequested;
      public event EventHandler? ContextMenuRequested;
      public void ApplyPlacement();
  }
  ```

**Requirements — `MiniPlacement.Fit`:**

- `Top` docks to `workArea.Top`; `Bottom` docks to `workArea.Bottom - size.Height`.
- The X coordinate is `desiredLeft` clamped to `[workArea.Left, workArea.Right - size.Width]`.
- `desiredLeft` null means "never placed": default to the **right-hand end**, `workArea.Right - size.Width`, which is where a status strip belongs and where it is least likely to sit under something.
- A strip wider than the work area aligns to `workArea.Left` rather than producing a negative clamp range.
- Pure and total: no exception for any input, including a zero-size work area.

**Requirements — the strip:**

- `WindowStyle="None"`, `ResizeMode="NoResize"`, `ShowInTaskbar="False"`, `SizeToContent="WidthAndHeight"`, `Topmost="True"`, `AllowsTransparency="False"`. Topmost is unconditional and is not the widget's pin: an edge strip that other windows cover is not an always-visible strip.
- Themed exactly like the widget: `WidgetWindowBackgroundBrush`, a 1px `WidgetWindowStrokeBrush` border, `WidgetFontFamily`, `UseLayoutRounding`, `SnapsToDevicePixels`. Corner radius: square on the docked edge, rounded on the free edge — or square all round if that proves fiddly; do not leave it half-styled.
- Content is an `ItemsControl` over `Providers` in a horizontal `StackPanel`. Each item shows, in order:
  - the monogram in the same treatment the card uses,
  - a `QuotaBar` for `PrimaryWindow`, `Width="44"`, the strip's bar height (4 px), using the same `QuotaBarFillSelector` inputs the card row uses,
  - the percentage text from `PrimaryWindow.UsedText`.
- A provider whose `PrimaryWindow` is null, or whose `UsedText` is null, renders the monogram, an **empty bar track** and the literal `—`. It must not render `0%` and must not render a filled bar.
- An item whose card `IsHiddenByFilter` is true is collapsed. Follow whatever `ProviderCardView` already does for this rather than inventing a second mechanism.
- Items are separated by a 1px vertical rule in `WidgetWindowStrokeBrush`; no separator before the first or after the last.
- At the right-hand end, one button: content `` (Segoe Fluent chevron) or `⌃`, `ToolTip` and `AutomationProperties.Name` both verbatim `Show the full widget`. Clicking it raises `ExpandRequested`.
- Left-dragging anywhere on the strip's background calls `DragMove()`, then on `MouseLeftButtonUp` re-applies `ApplyPlacement()` and saves `MiniLeft` through `SettingsService.Update`. The Y coordinate is never saved — the dock edge owns it.
- Right-click raises `ContextMenuRequested` so the host can show the same tray menu.
- Double-click on the background raises `ExpandRequested` as well.
- `ApplyPlacement()` calls `MiniPlacement.Fit` with `ScreenBounds.WorkAreaFor(this)` and the current `ActualWidth`/`ActualHeight`, then assigns `Left` and `Top`. It is called on `ContentRendered`, on `DpiChanged`, and on `SystemEvents.DisplaySettingsChanged` — subscribe and unsubscribe in the same guarded shape `WidgetWindow` already uses, including the `try`/`catch` around the subscription.
- The strip must **not** feed the widget's dismissal timer. It is always visible by design; a focus-loss dismissal would defeat the whole feature.
- Total strip height must land between 24 and 32 device-independent pixels with the default theme. State the measured value in the commit message.

**Acceptance criteria (tests to write):**

- `MiniPlacement.Fit` for `Top` returns `workArea.Top`; for `Bottom` returns `workArea.Bottom - height`.
- A null `desiredLeft` returns `workArea.Right - width`.
- A `desiredLeft` left of the work area clamps to `workArea.Left`; one past the right edge clamps to `workArea.Right - width`.
- A strip wider than the work area returns `workArea.Left`.
- `MiniWindowTests` (STA, via the existing `WpfFixture`): the window loads with a populated `MainViewModel` without throwing; with a card whose `PrimaryWindow` is null the rendered item contains `—` and not `0%`.

- [ ] **Step 1:** Write `MiniPlacement` and its tests first — it is the only part that can be proven without a screen.
- [ ] **Step 2:** Build the window and its code-behind.
- [ ] **Step 3:** Write the loading test; build and test as separate commands.
- [ ] **Step 4:** Commit — `feat: add the edge-docked mini strip`.

### Task 3: Switching between the two

**Files:**
- Modify: `src/AiUsageMonitor.App/Views/WidgetWindow.xaml` (tray menu), `WidgetWindow.xaml.cs`
- Test: `tests/AiUsageMonitor.App.Tests/WidgetWindowTests.cs`

**Interfaces:**
- Consumes: `MiniWindow`, `MiniPlacement` (Task 2), `AppSettings.MiniMode` (Task 1).
- Produces: `WidgetWindow.EnterMiniMode()`, `WidgetWindow.LeaveMiniMode()`, and a `_mini` field.

**Requirements:**

- The tray menu gains `<MenuItem Header="Mini mode" IsCheckable="True" Click="TrayMini_Click" />`, placed **after `Settings` and before `Diagnostics`** — the `Diagnostics` item was added by the diagnostics increment, which lands before this one. If it is absent, put `Mini mode` after `Settings` and say so in the report. Its `IsChecked` is set from `_settings.Current.MiniMode` each time the menu opens, in `OnTrayContextMenuRequested`.
- `EnterMiniMode()`: writes `MiniMode = true` through `SettingsService`, hides the widget **without** showing the tray hint balloon (the strip is on screen — nothing has disappeared), creates and shows the `MiniWindow`, wires `ExpandRequested` to `LeaveMiniMode` and `ContextMenuRequested` to `OnTrayContextMenuRequested`.
- `LeaveMiniMode()`: writes `MiniMode = false`, closes and nulls the strip, then shows the widget through the existing `ShowFromTray()` so focus, tick cadence and the dismissal timer all follow the one path that already handles them.
- `ShowFromTray()` gains a first line that leaves mini mode if it is on. Every entry point — tray `Open`, tray `Settings`, the global hotkey, the single-instance `ShowMessage` — already funnels through it, so this one line is what makes the exclusivity rule hold everywhere. **Guard against re-entry**: `LeaveMiniMode` calls `ShowFromTray`, so the check must be "the strip exists" and must null the field before calling on.
- **Tick cadence:** `TickCadence.For(isVisible: …)` must answer true when *either* window is on screen. Add a private `UpdateTickCadence()` that computes it from `Visibility == Visibility.Visible || _mini is not null` and assigns `_tick.Interval`; call it from `ShowFromTray`, `HideToTray`, `EnterMiniMode` and `LeaveMiniMode` instead of assigning the interval inline in each. A strip updating its countdowns once every five seconds is visibly wrong.
- `HideToTray()` when the strip is showing must **not** fire the tray hint balloon and must not change the strip.
- `OnClosed` closes the strip if one exists, before the tray icon is disposed.
- On startup, `OnContentRendered` enters mini mode when `settings.MiniMode` is true — and must then not leave the widget visible.
- `OnSettingsChanged` reconciles: if `settings.MiniMode` is true and `_mini` is null, enter; if false and `_mini` is not null, leave. This is what makes the settings-window checkbox work without a second code path.

**Acceptance criteria (tests to write):**

- `EnterMiniMode` sets `MiniMode` true and leaves `Visibility` not `Visible`; `LeaveMiniMode` sets it false and the widget visible.
- After `EnterMiniMode`, `ShowFromTray()` leaves mini mode and does not throw or recurse.
- `TickCadence` is the visible cadence while the strip is showing and the widget is hidden.
- Entering mini mode does not set `TrayHintShown` and does not raise a balloon.
- Toggling `MiniMode` through `SettingsService` alone enters and leaves the mode.

- [ ] **Step 1:** Add the mode transitions and the cadence helper.
- [ ] **Step 2:** Wire the tray menu item and the startup path.
- [ ] **Step 3:** Write the tests; build and test.
- [ ] **Step 4:** Commit — `feat: switch between the widget and the mini strip`.

## Out of scope

- Vertical (left/right edge) docking. Top and bottom only; a vertical strip is a different layout, not a different constant.
- Auto-hide, slide-in, or reserving screen space with an AppBar. The strip is an ordinary topmost window.
- Showing more than the primary window per provider. C19 is explicit: monogram, bar, percent, nothing else.
- Any change to compact density, which stays what it is.
