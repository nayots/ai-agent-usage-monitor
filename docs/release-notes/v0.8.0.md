## Highlights

**The Claude Code card no longer goes blank three times a day.** Claude Code's stored sign-in lasts
eight hours. When it lapsed, the card stopped reporting and stayed stopped until you opened a
terminal and ran `claude`. Now the widget asks Claude Code to renew its own sign-in and carries on
with the reading.

**It does that without ever touching your credentials.** The application does not read, refresh,
write or transmit a token to renew anything. It runs Claude Code's own command and then looks at
one non-secret number — when the stored expiry moved, the sign-in was renewed by the tool that owns
it.

**There is a switch, in Settings → Providers, and it starts on.** Renewing means Claude Code
rewrites its own credential file while you are not looking, which is a small thing to do on someone
else's behalf without telling them.

---

## Why

Two numbers explain the whole release. The access token lasts **8 hours**; the refresh token beside
it lasts about **30 days**. Nothing was ever broken when the card went blank — the sign-in was
healthy, and one short-lived half of it had simply lapsed — but a widget cannot tell you that in a
way you can act on without leaving the widget.

A tool whose whole purpose is to be glanceable is worth very little when it is blank for a third of
every day and the fix is a terminal.

## How the renewal works

When the stored expiry has passed, or the usage endpoint rejects the token, the widget runs
`claude doctor` once and re-reads the credential file. Claude Code renews its own sign-in as a side
effect of that command, and the reading then proceeds normally. On a rejected token the request is
retried exactly once; a second rejection is reported as it always was.

Success is judged only from the credential file — never from an exit code, and never by reading
what the command printed. The renewal counts when the stored expiry is readable, **has changed, and
is still in the future**. Each of those three matters: without "changed", a token the server
rejected while the file still called it live would be retried unchanged; without "still in the
future", a rotation to another already-spent token would send a request that could only fail.

A renewal is attempted **once per lapsed sign-in**. If it does not help, nothing is run again until
the stored sign-in changes — so a machine where this cannot work does not launch a process every
two minutes forever.

## What it will not do

- It will **not** refresh, rotate, read, store or transmit any token. That stays Claude Code's job.
- It will **not** install anything. `claude update` renews a sign-in too, but it installs a new
  Claude Code version as a side effect, which would override anyone who has deliberately set
  `DISABLE_AUTOUPDATER`.
- It will **not** run when the refresh token itself has expired. No command can help then, and the
  card says so and asks you to sign in.
- It will **not** open a console window, and it costs no quota — the command it runs never starts a
  model turn.

## Measured, not assumed

Verified live against Claude Code 2.1.263 on Windows 11:

| | |
|---|---|
| A sign-in lapsed while the widget was running | the next poll renewed it **46 seconds** later |
| A sign-in already lapsed when the widget started | renewed **1.1 seconds** into the first reading |
| Readings over a 12-hour run | **365 attempts, 365 successes**, no failures and no throttling |
| Error states shown to the user | **none** |

`claude auth status` was also tested and does **not** renew a sign-in, so it is not used.

## Diagnostics

Every renewal is now recorded twice: in the provider's notes, which you can read under
Settings → Diagnostics, and in the application log on disk, which outlives the process. An attempt
and a renewal are recorded at information level; a command that could not run, or that ran without
changing anything, is recorded as a warning. No credential appears in either, and a failure records
the kind of error rather than its message.

## Notes

The Claude Code usage mechanism remains **unofficial and undocumented**, and is labelled that way
throughout the application. This release does not change that: it makes the supported mechanism
survive an ordinary expiry instead of failing at one.
