## Highlights

**Quota rows can now tell you when a window will run dry.** On a window being spent faster than
time is passing, the expanded row states how far ahead of its reset the quota lands at the current
pace — `At this pace, spent ~3d early`. It is deliberately quiet: a window tracking at or under an
even pace says nothing at all.

**Codex reports more of what it actually knows.** Spend limits on business and enterprise seats
become a quota window of their own, and early-reset credits are surfaced instead of being dropped.

**Claude sign-in problems are recognised before a request is spent on them**, and your plan and
rate-limit tier now show on every window.

## Pace projection

Shown on the expanded quota row, controlled by **Show pace projection** in Settings → Appearance,
on by default.

The rate is the average since the window started — used percentage divided by elapsed time, taken
from the reading on screen. Nothing is sampled over time and no history is stored, so the sentence
beneath the bar and the elapsed-time marker on it are two renderings of the same arithmetic and
cannot contradict each other.

It stays silent unless it has something worth saying. Nothing is shown when:

- the window is tracking at or under an even pace — there is no reassurance message;
- less than 10% of the window has elapsed, where a single burst would dominate the estimate;
- the shortfall is under 2% of the window, which is noise rather than a warning;
- the provider has not reported a percentage, a reset instant, or a derivable window length;
- the card has gone stale. This one matters most: with the percentage frozen and the clock still
  running, a projection does not freeze — it slides steadily later and reads as good news about a
  provider that has stopped answering.

The wording is conditional on purpose. "At this pace" and the `~` mark it as an inference from a
rate continuing, which is the assumption most likely to be wrong — the projection cannot tell
whether a window was spent evenly or in one burst twenty minutes ago. It raises no notification.

## Codex

- **Spend limits become a quota window.** Read from the app-server's own `individualLimit`, which
  is populated on business and enterprise seats and absent on `plus`. It reports a *remaining*
  percentage rather than a used one — a client that assumes otherwise renders a limit 5% consumed
  as 95% consumed — so this is mapped from the CLI's generated protocol schema rather than from any
  third-party description of it. It carries no period length, so it gets no elapsed marker instead
  of a guessed one.
- **Early-reset credits are surfaced** rather than silently dropped. These reset a limit ahead of
  schedule and are reported alongside the windows rather than inside one.
- **The app-server is launched read-only and untrusted.** Defence-in-depth only — this application
  never opens a session — and verified to return a byte-identical response.

## Claude Code

- **An expired sign-in is recognised before the request is sent.** A doomed call is not free; it
  still counts toward the throttling behind this provider's 120-second floor. The check can only
  ever skip a call it is confident would fail — an implausible or missing timestamp falls through
  and sends the request exactly as before, so a fault in it can never disable a working widget.
- **The message tells you which fix applies**: while the refresh token is live, running any Claude
  Code session repairs the sign-in; once it has expired, only a fresh sign-in will.
- **Your plan and rate-limit tier appear on every window**, read from the same local file as the
  credential and costing no extra request.

## Widget

- **The window now grows to the screen it is on** before its provider list starts scrolling. The
  previous 520px cap was measured against healthy cards; two providers failing at once overflowed
  it, which put the least readable state behind a scroll bar. Short screens keep the previous
  behaviour exactly.
- **Failure notices lost the sentence that restated their own title.** The provider's own reason is
  now the message; the full text remains on hover.

## Install

Download `AiUsageMonitor.exe` and run it. No installer, no runtime prerequisite, no administrator
rights. If your machine blocks bare `.exe` downloads, take the `.zip` instead — it contains the
same executable.

Verify the download against `AiUsageMonitor.exe.sha256`:

```powershell
Get-FileHash AiUsageMonitor.exe -Algorithm SHA256
```

Claude Code usage is read through an endpoint the vendor does not document, and is labelled
**Unofficial** wherever it appears. It may stop working without notice; when it does, the card
reports an error rather than showing a stale or invented number.
